## Surprises vs architecture assumptions

Facts only; the U2 (commercial use) and provider-confirmation decisions are not made here (T-04, T-05 are the user's).

1. **Non-commercial restriction is confirmed, and its definition is narrow.** The free tier excludes "Websites or apps that have subscriptions or display advertisements" and "Commercial products or promotional activities"; tip jars and voluntary donations are allowed. This matches the architecture's "non-commercial only" assumption; whether the product falls on either side is for U2.
2. **HTTP status for exceeded limits is NOT CONFIRMED.** Architecture 3.x / item 5 assumes a 429 mapped to `rate_limited`; no official page states the status code. Not tested by deliberately exceeding the limits.
3. **Limits are higher than architecture assumed ("low thousands per day"):** 600/min, 5,000/hour, 10,000/day, 300,000/month, applied per IP address and application. Cloud hosts such as Vercel or Netlify may be limited earlier. The per-IP basis for a browser SPA means each user's own IP counts, but any server-side proxy or shared host would pool users (relevant to U5 and any proxy).
4. **CORS is not documented.** Architecture says "designed for direct browser calls". Official pages say nothing about CORS; only live headers (`access-control-allow-origin: *`) support browser use. No real browser test was done.
5. **Attribution is a UI requirement:** a link "next to any location Open-Meteo data are displayed" (example text "Weather data by Open-Meteo.com", linking to https://open-meteo.com/). Geocoding data needs "Location data based on GeoNames"; no exact wording or link target is mandated for GeoNames. Architecture said "CC BY 4.0 link; geocoding credit GeoNames": consistent, but the placement rule (next to each displayed location) should be reflected in the UI tasks.
6. **Reverse geocoding: not documented** (observed 404 on `/v1/reverse`). This matches the architecture's "no reverse geocoding" belief, but it is an absence of documentation plus one probe, not an official statement.
7. **Time zone is returned** (IANA identifier with `timezone=auto`), so architecture 3.1/3.5 assumption holds. One documented caveat: DST changes inside the requested range are ignored for the offset.
8. **Forecast days are selectable (0 to 16, default 7)** and today is the first day (docs anchor at "0:00 today"; observed). Assumption holds. The docs do not explicitly say "today counts as day 1".
9. **Stability of the geocoding `id` and guaranteed presence of `admin1` / `timezone` on every result are NOT CONFIRMED.** Architecture 3.4 uses the identity key for duplicate detection and favorites; the user may want this noted before relying on `id` alone.
10. **Terms page records coordinates in server logs for 90 days** (not shared with third parties). Relevant to the privacy position in architecture 5.2 / Q28.
